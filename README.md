# NEXUS

**An AI-powered Personal Knowledge Management System that answers from *your* knowledge — and proves it with citations.**

Status: **working scaffold.** Schema, retrieval, grounding contract, API, worker, and UI are implemented and tested. See [Roadmap](#status-what-works-today) for what is real versus stubbed.

---

## The one rule everything follows

> NEXUS never answers from a language model's general memory. Every claim comes from a retrieved passage of your own data, cited down to the document and page.

That rule is enforced in code, not in a prompt:

- Retrieval runs before every generation. There is no "chat without context" path.
- Citation markers generated by the model are **untrusted input**. The server resolves them against the actual source set, strips fabricated markers, and logs a `grounding_violation`.
- If retrieval finds nothing, the **LLM is never called**. A deterministic refusal is returned with `grounded: false`.
- Row-level security constrains every table, so a forgotten `WHERE user_id` cannot cross tenants.

The tests assert all four. If they pass, the system cannot silently invent an answer.

## Stack

| Layer | Choice | Where |
|---|---|---|
| Frontend | SvelteKit · Tailwind · TypeScript | `apps/web` → Vercel |
| Application | Python FastAPI (JWT auth, RAG orchestration) | `apps/api` → Fly.io `web` |
| Background | Python worker + Postgres job queue | `apps/api` → Fly.io `worker` |
| Data | Supabase Postgres + pgvector + RLS | `supabase/migrations` |
| Storage | Supabase Storage, private bucket, signed URLs | migration `0009` |
| Auth | Supabase Auth (JWKS-verified in FastAPI) | — |

```
Capture ─▶ Storage ─▶ [jobs table] ─▶ Worker: extract → chunk → embed ─▶ pgvector
                                                                            │
Question ─▶ embed ─▶ hybrid_search (vector + keyword, RRF, similarity gate) ┘
                          │
                          ▼
                 context + numbering ─▶ LLM ─▶ answer + resolved citations
```

## Quick start

```bash
make install              # deps + apps/api/.env and apps/web/.env.local from
                          # their templates (fill in Supabase keys after `supabase start`)
supabase start            # local Postgres / Auth / Storage
make db-reset             # migrations + seed
make dev                  # API :8000, web :5173
```

Sign in as `alice@nexus.local` / `password123` and ask *"Where do my deployment secrets live?"* — you should get an answer with a citation chip pointing at the seeded note.

| Command | Does |
|---|---|
| `make test` | unit tests (offline, no providers) |
| `make test-db` | schema, RLS, retrieval, grounding e2e |
| `make lint` | ruff + mypy + svelte-check |
| `make worker` | background processor |

## Status: what works today

**Real and tested**

- 20 tables, 71 RLS policies (67 on public tables, 4 on `storage.objects`), HNSW + GIN indexes; 13 migrations apply in order
- `hybrid_search()` — RRF fusion with an absolute cosine-similarity gate, `security invoker`, so RLS applies inside it
- AI layer split into pipeline stages (`ai/providers`, `ingestion`, `retrieval`, `rag`, `knowledge`, `summarization`)
- Grounding contract: fabricated markers stripped, refusal path never calls the LLM
- Postgres job queue: `SKIP LOCKED` claim, exponential backoff, dead-letter, staleness sweep
- Ingest pipeline: download → extract (PDF/DOCX/TXT/MD/HTML) → clean/normalize → chunk (700/100) → embed → version-guarded write → summary + entities → mark completed
- 53 API route handlers covering documents, notes, collections, tags, search, chat (SSE), conversations, graph, jobs, workspaces, audit
- SvelteKit UI: auth, dashboard, streaming assistant with citation chips, documents with honest per-stage progress, notes, search with `matched_arm`, graph, settings
- Rate limiting wired at every provider-calling endpoint (`app/core/guard.py`), per user **and** per workspace
- Role enforcement at 17 call sites: a `viewer` is refused writes with `insufficient_role`
- Boot-time schema guards (`app/core/schema_guard.py`): a model/dimension disagreement with the `vector(1536)` column stops the process instead of failing on the first chunk
- Verified: 261 unit tests, 99 database tests, 66 frontend unit tests, 0 type errors, clean lint

**Stubbed or pending**

- Entity/summary extraction runs but was validated with a fake LLM — needs a live provider to judge quality
- `pg_trgm` is isolated in migration `0010`, which is the one migration a minimal Postgres can skip (suggestions degrade to exact-prefix matching)
- No OCR: scanned PDFs fail loudly with `no_text_layer`
- Eval set described in `docs/RAG-PIPELINE.md` §5 is not yet populated with real questions
- Entity merge/rename (ROADMAP M5) is not implemented: the graph reads entities, it cannot yet curate them

## Non-negotiables

1. Service-role and AI keys never reach the browser. The frontend reads `PUBLIC_*` only.
2. RLS enforces tenancy; application filters are a second, redundant layer.
3. No answer without a source — `citations: []` with `grounded: false` is a correct response.
4. No silent partial success. Failed ingest says why; slow ingest names its stage.
5. Retrieved text is data, never instructions.
